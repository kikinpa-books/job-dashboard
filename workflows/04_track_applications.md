# Workflow 04: Track Applications

## Objective
Keep the Google Sheet tracker accurate and the Dashboard current after every run.

## Google Sheet Structure

**Tab 1: Applications**
| Column | Field | Notes |
|--------|-------|-------|
| A | job_id | Unique ID (e.g. linkedin_123456) |
| B | date_applied | YYYY-MM-DD |
| C | company | |
| D | title | |
| E | location | |
| F | platform | LinkedIn / Indeed / Glassdoor / Direct |
| G | apply_url | |
| H | status | Applied / Interviewing / Offer / Rejected / Withdrew / Error |
| I | follow_up_sent | Date sent, blank if not yet |
| J | notes | Error messages, contact name, interview notes |
| K | cover_letter_used | Filename |
| L | salary_listed | From the listing |
| M | easy_apply | TRUE or blank |
| N | date_last_updated | Auto-set on every write |

**Tab 2: Follow-Up Log**
Append-only log of every follow-up sent. Never edit rows here.

**Tab 3: Dashboard**
Auto-generated by `tools/update_dashboard.py`. Do not edit manually.

## Updating Application Status

When you receive a response (interview invite, rejection, offer), update the status:
```
python tools/update_application.py --job_id "<job_id>" --field "status" --value "Interviewing"
```

Valid status values: `Applied`, `Interviewing`, `Offer`, `Rejected`, `Withdrew`, `Error`

## Refreshing the Dashboard

Run this after every apply session or follow-up session:
```
python tools/update_dashboard.py
```

The Dashboard tab shows:
- Total applications and breakdown by status
- Applications by platform
- Last 10 applications (most recent first)
- List of applications that need a follow-up

## Notes for the Agent
- The Sheet is the single source of truth. Never assume something was applied to without a row in the Sheet.
- If a row shows status "Error", the application was not submitted. Retry it in the next run or flag for manual review.
- The user may update status columns manually (e.g., marking "Interviewing" after a call). Respect those values.
